# Homepage design

Surface detail split from [DESIGN.md](../../../DESIGN.md), which holds the identity, tokens, and rules for every page and wins on conflict. Read this file when changing this surface.

## Homepage portrait hero

The homepage portrait ships as `public/images/gabo-portrait.webp`, generated from `assets/homepage/v2/gabo-portrait.png` (no facial retouch; production steps in [docs/agents/images.md](../images.md#homepage-portrait-hero)). `PortraitMedia` overlays crisp SVG geometry in empty background coordinates only: a partial arc, sparse grid and dot reticle, vertical axis with PRODUCT, DESIGN, ENGINEERING, and DELIVERY, and a small plus near the collar. No glow, bloom, shadow, or decorative gradient.

The split layout uses normal grid flow. The left column contains the white H1 and the muted name/turquoise role; there is no pitch paragraph, because the headline already carries the core line. The row centers the copy against the portrait, which grows into the right margin from `xl` (`xl:w-[118%]`) without narrowing the copy column. On desktop the hero starts 24px lower (`lg:mt-6`). The search field sits 40px (mobile) to 80px (desktop) beneath the hero, and from `lg` it is inset 32px from each content edge so it reads as an invitation rather than a divider (mobile uses the page gutters); the gap to Selected work is unchanged. Its placeholder is “Ask me what I built for LegalAgent” from 640px (`searchCopy.homePlaceholder`; the dialog and phones keep the shared placeholders). Mobile stacks without clipping. The personal OG composites this same portrait and linework (`lib/portrait-overlay.ts`) beside the H1, muted name, and turquoise role. Every other landing page gets the same card with its own headline; no project OG or hero is replaced by homepage covers.

## Editorial homepage

`homeColumn`, `sectionGap`, `editorialGrid`, `editorialLink`, `heroTitle` and `heroPitch` extend the existing spacing system. `SiteWidth` applies that homepage shell on every route. It does not import page content into a client graph. Navigation, main and footer share width. Narrative copy stays on `readingMeasure`. The résumé keeps its screen measure. CV print width stays unchanged.

Selected work (`components/home/featured-work.tsx`, homepage only; `/work` keeps `EditorialProjectList` and its filtered layouts) is one lead case and then a quieter row. The set still comes from `projectsFromSlugs(homepageEditorialSlugs)`. LegalAgent leads at about 60% of the row (`3fr/2fr`, 28–36px gutter from `lg`): its package 16:9 cover beside role · year from the project record, the case title at `text-5xl`, one contribution line (homepage copy supported by the LegalAgent story) and “Read the case study ↗”, vertically centered and left aligned on black with no card surface. Wink, ZTX and Bitlauncher follow in three 16:9 columns from 768px with left-aligned names and one-line captions, linked to their case pages. Below 1024px the lead stacks (image, story, link); below 768px the supporting projects stack. The lead image link is `aria-hidden` and out of the tab order, so each case has one focusable link with no nesting; the supporting cards are single links. Package facts remain authoritative for image paths and role/year; alt text uses the project title.

Under the projects, a lightly ruled “Explore by focus” row (`components/home/focus-row.tsx`) links “Agentic AI products” to `/ai` and “Onchain finance” to `/web3`; it replaces the standalone Focus section. Writing follows as `LatestPosts`. Every Writing list on the site (homepage, `/blog`, `/ai`, `/web3`, `/bio`, project, tech and article rails, and GenUI writing results) renders the same `EditorialBlogList`: muted date, linked title, ↗ arrow and hairline dividers, with no summaries. The page has no closing invitation of its own: “Start a conversation ↗” to `/contact` sits in the footer's right column on every route, over the approved hire line (location line from `lib/hire-terms.ts`), so the invitation appears once and the footer keeps its utility links. `/contact` is just the invitation and the form, and the full hire terms live in the 1099 post, the CV and the llms index. Writing uses four latest dated editorial entries. There is no Career section; `/bio` is in the nav and links to `/cv`.

The homepage field is a real inline field (`HomepageGenUiShell`): visitors type and pick suggestions in place, and only on Enter or a picked suggestion does the one full-screen search overlay (`SiteSearchShell`/`SiteSearchPanel`) open, running that query, with the field animating from its place to a fixed bar at the top. The nav icon and Cmd/Ctrl+K open the same overlay on every route without animating from the page field ([decision 0002](../../decisions/0002-unified-search-overlay.md)). It follows one search contract ([spec 001](../../specs/001-site-design-ux-search.md#shared-search-contract)): one state machine (`useGenuiComposition`), one outcome region (`GeneratedRegion`), one copy table (`lib/search/copy.ts`) and one keyword ranker (`lib/search/keyword-rank.ts`) over one record set (the agent index, via `lib/site-search-records.ts`), so keyword matches and MCP `search_site` rank the same pages in the same order for the same text. Both call `/api/genui/compose` on Enter from a `type="text"` combobox with no visible badge (the accessible name stays "Search this site (beta)"). Enter-only, IME-safe, no submit button, no theme toggle or send control on the field. Escape closes suggestions first, then the dialog, and never clears text. The suggestions list is named "Suggestions" with "Recent" and "Examples" groups; focus stays in the field, and Recent keeps only queries that reached a result. The field and Recent show the visitor's own words: a clicked suggestion shows its label, while its canonical query stays internal for routing (a Recent example routes on it again). A back arrow outside the field, to its left, is the overlay's one visible exit ("Close search"; Escape also closes), so there is no close X on the right. A small × inside the field, at the trailing edge, shows only while the field has text; it is "Clear search", resets and refocuses the field and never closes the overlay. Emptying the field by hand does not reset results. Usage hints are screen-reader only on both surfaces. Cmd/Ctrl+K works everywhere, including inside inputs, and the nav Search control focuses the homepage field on `/` or opens the dialog elsewhere; Cmd/Ctrl+K closes an open dialog, and closing returns focus to whatever opened it. The `⌘K` / `Ctrl K` hint shows only on fine pointers, from 640px, in the trailing slot of either field while it is empty; typing swaps it for the clear ×. The overlay's field and results fill the site column exactly (`siteColumn`, the width of the page content); only the back arrow hangs outside it, in the gutter from 1280px, and over the search icon below that. The conversational placeholder stays approved for sighted users from 640px; below 640px it is "Ask about my work…" (the accessible name is unchanged). Without JavaScript, the homepage field falls back to browse/contact copy. Results render inside the overlay and no longer replace homepage SSR sections. The overlay is full screen on every route (`100dvh`, solid `bg-black`, no blur), keeps suggestions inside the panel, has a sticky field with safe-area padding, fades in over 200ms and out over 150ms on the site curve while the field bar glides from its trigger (no animation under reduced motion), scrolls generated results in-panel, and shares the homepage session providers (`GenuiSessionProvider`, so booking and contact flows render in both). The dialog's composition and session providers live in `SiteSearchShell`, above the dialog, so closing and reopening it keeps the last result, drafts and receipts for the session; the in-field × resets them. Both surfaces show a static status line at once and a shimmer only after 300ms: "Composing results…", then one quiet human label per stage from the stream's `stage` events ("Planning…", "Finding projects…", "Finding posts…", "Checking the résumé…", "Checking availability…", "Writing the answer…"; never tool names, and not announced). A Stop control sits beside the status line, never in the field; it aborts the request, keeps the field text and drafts, and ends in "Stopped." with Try again. The client gives up after 20s with the timed-out copy. A settled result ends with a source line from its records ("Based on 4 projects and 2 posts"), and each generated block reveals with the `enter` values (200ms, opacity 0→1, scale 0.97→1, site curve; 120ms opacity only under reduced motion), keyed by request, in CSS (`app/global.css`), not `<ViewTransition>`. An off-topic query ends in an explicit empty state ("No answer for that on this site.", keyword matches, three example chips). Errors are typed: rate-limited shows the server's message, the server's 15s deadline shows "That took too long. Try again.", anything else shows "Search is unavailable right now."; every error shows Try again (re-runs the last submitted query and refocuses the field), keyword matches and links to `/work`, `/cv` and `/contact`, identically on both surfaces. Only a result announces "Results ready." GenUI booking and note writes keep one retry identity per draft; after a network failure (no server answer, so the write may exist) the draft's fields lock and the identity is kept until a retry gets a definite answer, so an edit cannot become a second, different write. Sticky prompt behavior and capability specs remain in `docs/specs/homepage-genui/`. `/ask` redirects to `/`.

Alternative project arrangements are documented in [the v2 implementation scope](../../specs/design-system-v2/IMPLEMENTATION.md) for future GenUI use, not competing homepage layouts. GenUI project browsing uses approved editorial recipes (`project-timeline`, `project-bento`, `project-feature-grid`, `project-asymmetric-closing`, `project-compact-list`, `project-comparison`) with dark hairline cards, package images via `resolveProjectImage`, and turquoise project links. `project-timeline` is the default for four or more browsed projects (up to eight): one column, newest first by `year`, the year in the margin (shown once per year), and a compact card with a small cover, title, role, two-line description and link. Browse results are the "what have you built" case, so date order applies there; `project-bento` and `project-asymmetric-closing` stay valid recipes for authored documents but are no longer auto-selected. In every recipe a card sizes to its content: only cards sharing a row share that row's height, and no card spans rows. `project-bento` is a wide lead plus three equal cards. `project-comparison` shows the projects as two or three balanced columns, then one aligned, always-visible row per requested dimension (role, technical work, what shipped, stack, categories, year; default role, what shipped, stack). Rows quote package fields only; a missing field reads “Not recorded”. GenUI project recipes do not add eyebrow labels or section headings above the evidence, and an answer does not relist sources that already render as evidence beside it. capability diagrams are reserved for explicit architecture intent, not domain keywords alone. Curated homepage suggestions and equivalent canonical queries share one deterministic route (intro + evidence via `ExperienceStack` when needed). Large project sets use a visual lead recipe plus a compact list remainder so every published match stays reachable. FinTech browse is limited to package-backed slugs in `lib/genui/fintech-projects.ts` (currently Wink). CV results use the `cv-preview` composite (HTML from `resolveCv`, not duplicated JSX facts).
