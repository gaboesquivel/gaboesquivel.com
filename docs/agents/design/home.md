# Homepage design

Surface detail split from [DESIGN.md](../../../DESIGN.md), which holds the identity, tokens, and rules for every page and wins on conflict. Read this file when changing this surface.

## Homepage portrait hero

The homepage portrait ships as `public/images/gabo-portrait.webp`, generated from `assets/homepage/v2/gabo-portrait.png` (no facial retouch; production steps in [docs/agents/images.md](../images.md#homepage-portrait-hero)). `PortraitMedia` overlays crisp SVG geometry in empty background coordinates only: a partial arc, sparse grid and dot reticle, vertical axis with PRODUCT, DESIGN, ENGINEERING, and DELIVERY, and a small plus near the collar. No glow, bloom, shadow, or decorative gradient.

The split layout uses normal grid flow. The left column contains the white H1, muted name/turquoise role, and an end-to-end pitch. The full-width search sits beneath both columns. Mobile stacks without clipping. The personal OG composites this same portrait and linework (`lib/portrait-overlay.ts`) beside the H1, muted name, and turquoise role. Every other landing page gets the same card with its own headline; no project OG or hero is replaced by homepage covers.

## Editorial homepage

`homeColumn`, `homeSection`, `editorialGrid`, `editorialLink`, `heroTitle` and `heroPitch` extend the existing spacing system. `SiteWidth` applies that homepage shell on every route. It does not import page content into a client graph. Navigation, main and footer share width. Narrative copy stays on `readingMeasure`. The résumé keeps its screen measure. CV print width stays unchanged.

Selected work is LegalAgent, Wink, ZTX and Bitlauncher in `EditorialProjectList`. The grid is one column until the editorial container is `48rem` wide, then two columns. `EditorialProjectCard` shows the package `image` URL (site-relative via `resolveProjectImage`) in a 16:9 frame, plus name, verified `role`, and description in `projectCardDescription` (`line-clamp-3`, shared with `FeaturedProjectCard` and filtered work grids). Package facts remain authoritative for image paths and alt text uses the project title.

Focus uses lightly ruled typographic links. Writing uses four latest dated editorial entries. Career uses two compact links. Work together retains the existing hire terms. Footer content stays unchanged.

Homepage generative search (`HomepageGenUiShell` / `PromptField`) and the off-homepage search dialog follow one search contract ([spec 001](../../specs/001-site-design-ux-search.md#shared-search-contract)): one state machine (`useGenuiComposition`), one outcome region (`GeneratedRegion`), one copy table (`lib/search/copy.ts`) and one keyword ranker (`lib/search/keyword-rank.ts`) over one record set (the agent index, via `lib/site-search-records.ts`), so keyword matches and MCP `search_site` rank the same pages in the same order for the same text. Both call `/api/genui/compose` on Enter from a `type="text"` combobox with an outline **Beta** badge at the trailing edge (hidden from assistive tech; the accessible name is "Search this site (beta)"). Enter-only, IME-safe, no submit button, no theme toggle or send control on the field. Escape closes suggestions first, then the dialog, and never clears text. The suggestions list is named "Suggestions" with "Recent" and "Examples" groups; focus stays in the field, and Recent keeps only queries that reached a result. The field and Recent show the visitor's own words: a clicked suggestion shows its label, while its canonical query stays internal for routing (a Recent example routes on it again). The leading search icon becomes a back-arrow "Clear search" control once a search is active; it resets and refocuses the field, and emptying the field does not reset results. Usage hints are screen-reader only on both surfaces. Cmd/Ctrl+K works everywhere, including inside inputs, and the nav Search control focuses the homepage field on `/` or opens the dialog elsewhere; Cmd/Ctrl+K closes an open dialog, and closing returns focus to whatever opened it. The `⌘K` / `Ctrl K` hint shows only on fine pointers, from 640px, while the homepage field is idle and empty. The conversational placeholder stays approved for sighted users from 640px; below 640px it is "Ask about my work…" (the accessible name is unchanged). Without JavaScript, the homepage field falls back to browse/contact copy. Successful GenUI sessions replace homepage SSR sections below the sticky prompt (solid `bg-black`, hairline bottom border, no blur); the dialog matches the site column (`max-w-6xl` less gutters) with `rounded-lg`, a hairline border and solid `bg-black` over a `bg-black/60` overlay (no blur), keeps suggestions inside the panel, goes full height (`100dvh`) with a sticky field and safe-area padding below 640px, opens in 150ms from the top on the site curve (no animation under reduced motion), scrolls generated results in-panel, and shares the homepage session providers (`GenuiSessionProvider`, so booking and contact flows render in both). The dialog's composition and session providers live in `SiteSearchShell`, above the dialog, so closing and reopening it keeps the last result, drafts and receipts for the session; "Clear search" resets them. Both surfaces show a static status line at once and a shimmer only after 300ms: "Composing results…", then one quiet human label per stage from the stream's `stage` events ("Planning…", "Finding projects…", "Finding posts…", "Checking the résumé…", "Checking availability…", "Writing the answer…"; never tool names, and not announced). A Stop control sits beside the status line, never in the field; it aborts the request, keeps the field text and drafts, and ends in "Stopped." with Try again. The client gives up after 20s with the timed-out copy. A settled result ends with a source line from its records ("Based on 4 projects and 2 posts"), and each generated block reveals with the `enter` values (200ms, opacity 0→1, scale 0.97→1, site curve; 120ms opacity only under reduced motion), keyed by request, in CSS (`app/global.css`), not `<ViewTransition>`. An off-topic query ends in an explicit empty state ("No answer for that on this site.", keyword matches, three example chips). Errors are typed: rate-limited shows the server's message, the server's 15s deadline shows "That took too long. Try again.", anything else shows "Search is unavailable right now."; every error shows Try again (re-runs the last submitted query and refocuses the field), keyword matches and links to `/work`, `/cv` and `/contact`, identically on both surfaces. Only a result announces "Results ready." GenUI booking and note writes keep one retry identity per draft; after a network failure (no server answer, so the write may exist) the draft's fields lock and the identity is kept until a retry gets a definite answer, so an edit cannot become a second, different write. Sticky prompt behavior and capability specs remain in `docs/specs/homepage-genui/`. The top-right Search button uses the shared search behavior described above; `/ask` redirects to `/`. Homepage GenUI replacement below the prompt is active; moving the prompt itself is not.

Alternative project arrangements are documented in [the v2 implementation scope](../../specs/design-system-v2/IMPLEMENTATION.md) for future GenUI use, not competing homepage layouts. GenUI project browsing uses approved editorial recipes (`project-bento`, `project-feature-grid`, `project-asymmetric-closing`, `project-compact-list`, `project-comparison`) with dark hairline cards, package images via `resolveProjectImage`, and turquoise project links. `project-comparison` shows the projects as two or three balanced columns, then one aligned, always-visible row per requested dimension (role, technical work, what shipped, stack, categories, year; default role, what shipped, stack). Rows quote package fields only; a missing field reads “Not recorded”. GenUI project recipes do not add eyebrow labels or section headings above the evidence, and an answer does not relist sources that already render as evidence beside it. capability diagrams are reserved for explicit architecture intent, not domain keywords alone. Curated homepage suggestions and equivalent canonical queries share one deterministic route (intro + evidence via `ExperienceStack` when needed). Large project sets use a visual lead recipe plus a compact list remainder so every published match stays reachable. FinTech browse is limited to package-backed slugs in `lib/genui/fintech-projects.ts` (currently Wink). CV results use the `cv-preview` composite (HTML from `resolveCv`, not duplicated JSX facts).
