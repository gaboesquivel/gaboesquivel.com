# Layout and responsive behavior

Detail split from [DESIGN.md](../../../DESIGN.md), which holds the identity, tokens, and rules for every page and wins on conflict. Read this file when changing page shells, widths, grids, heroes, nav, footer, or media frames.

Source: [`app/layout.tsx`](../../../app/layout.tsx) and [`components/shared/spacing.ts`](../../../components/shared/spacing.ts).

- Column: `SiteWidth` applies `homeColumn` (`max-w-6xl`, `px-4 sm:px-6 lg:px-8`) on every route, including nav and `main`. `siteColumn` is the same shell. Long-form copy uses `readingMeasure` (`max-w-[65ch]`) inside that shell for narrative blocks inside editorial layouts. `/ai`, `/web3`, and `/bio` keep that shell and set narrative copy to `editorialMeasure` (`max-w-[72ch]`); project panels and photography use the full shell. **Interior layout families** (homepage stays locked; do not widen nav/footer):
  - **Family A — Index:** `/`, `/work`, `/work/[type]`, `/tech`, and similar listings stay on `siteColumn` only.
  - **Family B — Editorial:** `/bio`, capability routes, `/project/[slug]`, `/ai`, `/web3`, writing index, contact, explore. Opt in via `InteriorPageShell` for shared section spacing and 12-column splits (`SplitSection`); content stays inside the same `siteColumn` shell as home—no viewport breakout.
  - **Family C — Articles:** `/blog/[slug]` uses `ArticleShell`: one centered `articleColumn` (`max-w-3xl`) holding the eyebrow, title, date, body, and chips. No table of contents (no rail, no inline disclosure). Paragraphs, lists, quotes, headings, and wide or breakout figures fill that column (`.blog-content`); `BlogImage` modes `prose` / `wide` / `breakout` in `app/global.css`.
  - **Family D — Utility reading:** `/docs`, `/privacy`, `/about` use `ReadingPageShell` (one left-aligned `readingMeasure` inside `siteColumn`, no per-page width overrides, no breakout canvas). `/cv` print unchanged.
- **Section spacing ownership:** `EditorialSection` and standalone `SplitSection` apply `sectionGap`. Nested splits pass `sectionSpacing={false}` to avoid double major gaps.
- Post figures and code may exceed prose measure within the article column; breakout figures must not cause horizontal scroll. Hire lines in `LetsConnect` stay full shell, matching the homepage. The résumé document stays `max-w-4xl` on screen. `h-0.5 bg-accent` top bar. CV print stays `print:max-w-none`.
- Mobile first: one column below `md`. Default card grids go two-up at `md` (`twoColGrid` / `blockGrid`, `md:grid-cols-2`) — not bento
- **Exception:** `/explore` featured row uses `md:grid-cols-3` in `app/explore/page.tsx`; do not spread 3-up card grids elsewhere without an explicit task. The footer's three link columns are not a card grid.
- Homepage H1: all-white “Software for humans and agents.”, display scale in `heroTitle`; signature immediately beneath, name muted and current role turquoise. Its type, copy and portrait stay; only its top edge is shared with every other page ([decision 0003](../../decisions/0003-page-title-system.md)). **One title system:** every page h1 is `PageTitle` at the display `heroTitle` scale (52px max, 1.12 line height, same tracking), preceded by one fixed 36px row (`PageEyebrow`: the breadcrumb, or an empty spacer), so all titles start at the same x/y. `/work` and all `/work/[type]` routes share one persistent `WorkIndexHero` inside `app/work/layout.tsx`. The other routes (`/ai`, `/web3`, `/bio`, `/blog` and categories, capability routes, `/explore`, `/tech`, `/about`, `/contact`, `/privacy`, `/docs`, blog posts, project pages) open with `InnerPageHero`, `PageIntro` or `PageTitle`. Only embedded GenUI panels (`compact`) and the print-stable `/cv` use the smaller `pageTitle`. The opening word is a shared view-transition element (`TitleLead`): pages that open with the same word, such as `/` and `/work` ("Software"), keep it painted in place with no fade or move. Section rhythm is one token, `sectionGap` (64px mobile, 96px desktop); `narrativeIntroGap` is the only other major gap. `/ask` redirects to `/`.
- The primary nav wraps onto more lines on narrow screens (`flex-wrap`); there is no menu toggle. Items are `h-9` (36px) on fine pointers and `pointer-coarse:h-11` (44px) on touch. The items are `gabo`, `work`, `ai`, `web3`, `bio`, and `blog` (`components/layout/navbar.tsx`). `/ask` is not a nav item.
- `/ask` redirects to `/`. Booking and contact render as GenUI forms inside homepage search and the search dialog ([ask.md](ask.md)).
- Footer link lists use two columns below `sm`; the hire note spans the full width until `sm`, then the footer is three columns
- Page and project media: 16:9, `rounded-lg`, via `projectMedia`. Covers, project heroes, cards, GenUI project cards, and `/bio` chapter media use `object-cover`; per-slug focal positions and the intrinsic-width cap for small legacy sources live in `lib/work/project-cover.ts`. Adjust the focal position when a frame would crop the subject; do not edit the asset. The one `object-contain` frame is the project-page Artifacts gallery (`components/work/project-case-study.tsx`), which shows full screenshots on `bg-black`. Optional blog hero images and social exports follow [editorial-images.md](editorial-images.md); do not bake rounded corners into image files.

## Color pairs and chrome

- A light half of a `dark:` pair, when one remains, is `border-neutral-200`; on screen the `dark:` half renders (`border-hairline`, hover `neutral-800`). `neutral-500` may appear as a border or hover tint, never as text. `components/tweet.css` keys its dark values to `.dark`, not `prefers-color-scheme`.
- The primary nav has `aria-label="Primary navigation"` and marks the current page with `aria-current="page"`; the current item is `text-accent` with no underline.
