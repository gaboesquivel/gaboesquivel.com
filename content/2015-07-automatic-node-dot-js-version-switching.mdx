When working on multiple [Node.js](/tech/nodejs) projects it is important to configure your development environment to automatically switch to the right node version for a particular project. You can automate this in many different ways. I opted for a module called [avn](https://github.com/wbyoung/avn) that works both with [nvm](https://github.com/creationix/nvm) and [n](https://github.com/visionmedia/n) for automatic Node.[js](/tech/javascript) version switching. In my case I use nvm as my version manager. In order to achieve automatic version switching with avn you need to add a `.node-version` file at the root of your projects specifying the node version required.

After installing avn, when you cd into a directory with a `.node-version` file, avn will automatically detect the change and use your installed version manager to switch to that version of node. If that node version is not available, you have to install it yourself. avn won't try to do so; it will only attempt to switch to that version and notify you if it is not available on your environment.

As good practice, you should also specify that node version in the [engines field](https://docs.npmjs.com/files/package.json#engines) of package.json: `"engines": { "node": "0.12.7" }`

_Update, March 25, 2016_  
Kikobeats just released [nodengine](https://github.com/Kikobeats/nodengine), which does the same thing but reads from the engines field in package.json.
